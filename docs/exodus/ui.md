# Exodus - UI (home-hud)

[← Project Exodus](./README.md)

- **`/exodus/sources`** — table of sources with their linked host, and an Add Source modal. The host is optional.
- **`/exodus/sources/[id]`** — the latest job with queue counts (refreshes itself every 5 seconds while a job is active), Start Job, Mark Complete, Cancel Job (with confirmation), failed directories (with a Retry button only while their job is still active; a finished job's failures say to start a new job), a "Review candidates" link, and job history.
- **`/exodus/candidates`** — the review queue for [review candidates](./review-candidates.md), under the Exodus menu as "Review Candidates". A Source selector (`?source=<id>`, falling back to the first source) picks whose candidates to show. Filters: Decision (`pending` by default, so the page is the work queue; `approved`, `rejected`, `all`) and "Agent says" (`back_up`, `skip`, `needs_review`). All state lives in the URL (`source`, `decision`, `recommendation`, `after`; defaults are left out), the page is server-rendered, and 50 candidates load per page with Next/First page links. Each row shows the path and the agent's summary, folder/file, the agent's recommendation and confidence, the human decision, and when the recommendation last changed. Rows have **Approve** and **Reject** for pending candidates and **Details**, which opens a modal with the agent's reason, observations, still-unknown questions, git facts (unknowns shown as "unknown", never as "no"), content kinds, and any decision already made, plus an optional note and Approve / Reject / Reset to pending. A decision that the API refuses (an excluded path cannot be approved) shows its message and changes nothing. A decided candidate whose recommendation was updated later shows an "Agent changed" badge. Decisions go out as the default human actor; the agent has no decision tool. There is no bulk action yet.
- **`/exodus/rules`** — all exclusion rules, global and per source, with an Add Rule modal (applies to, path, scope, reason) and Remove with confirmation. Server actions post to the API; humans can create global rules here, the agent cannot.
- **`/exodus/audit`** — the audit log, newest first, filterable by source and event type (`?source=`, `?type=`), 50 per page with Newest/Older links (`before` cursor). Each row gets a one-line description built from the event's `details` (`lib/audit-display.ts`).
- **`/exodus/jobs`** — jobs across all sources, filterable by source through a `?source=<id>` URL parameter.
