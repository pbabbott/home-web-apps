# Exodus - UI (home-hud)

[← Project Exodus](./README.md)

- **`/exodus/sources`** — table of sources with their linked host, and an Add Source modal. The host is optional. The modal also holds the source's **file access** connection (type, username, domain, password, share mappings, and a Save and test button); the stored password is never sent back to the browser, so editing shows "Saved" and a blank field keeps it. Testing needs the source to exist, so it is disabled while adding.
- **`/exodus/sources/[id]`** — the latest job with queue counts (refreshes itself every 5 seconds while a job is active), Start Job, Mark Complete, Mark Failed (asks for a reason, shown on the job; for a broken run, where Cancel is for stopping a healthy one), Cancel Job (with confirmation), a "View job details" link, failed directories of the latest job shown above (with a Retry button only while their job is still active; a finished job's failures say to start a new job), a "Inventory items" link, and job history (each row links to the job's detail page).
- **`/exodus/inventory`** — the review queue for [inventory items](./inventory.md), under the Exodus menu as "Inventory". A Source selector (`?source=<id>`, falling back to the first source) picks whose inventory items to show. Filters: Decision (`pending` by default, so the page is the work queue; `approved`, `rejected`, `all`) and "Agent says" (`back_up`, `skip`, `needs_review`). All state lives in the URL (`source`, `decision`, `recommendation`, `view`, `after`; defaults are left out), the page is server-rendered, and 50 inventory items load per page with Next/First page links. Each row shows the path and the agent's summary, folder/file, the agent's recommendation with its confidence in gray parentheses beneath, the human decision, and when the recommendation last changed. Rows have **Approve** and **Reject** for pending inventory items and **Details**, which opens a modal with the agent's reason, observations, still-unknown questions, git facts (unknowns shown as "unknown", never as "no"), content kinds, and any decision already made, plus an optional note and Approve / Reject / Reset to pending. The modal also asks the API how exclusion rules treat the path: an excluded or selective-only path shows a notice with a link to `/exodus/rules` and Approve is disabled (the API would refuse it anyway). A decision that the API refuses (an excluded path cannot be approved) shows its message and changes nothing. A decided inventory item whose recommendation was updated later shows an "Agent changed" badge. Decisions go out as the default human actor; the agent has no decision tool. A Table / Cards toggle at the top (`?view=cards`; the table is the default) switches the layout. Each card is colored by the human decision (yellow for pending, green for approved, red for rejected) and shows everything the detail modal does inline, with Approve / Reject / Reset to pending and an optional reason; cards skip the per-item exclusion check, so an API refusal appears in the page-level error line. The single-column card layout suits a phone. There is no bulk action yet.
- **`/exodus/rules`** — all exclusion rules, global and per source, with an Add Rule modal (applies to, path, scope, reason), Edit (scope and reason only; the path and what the rule applies to are fixed) and Remove with confirmation. Server actions post to the API; humans can create global rules here, the agent cannot.
- **`/exodus/audit`** — the audit log, newest first, filterable by source and event type (`?source=`, `?type=`), 50 per page with Newest/Older links (`before` cursor). Each row gets a one-line description built from the event's `details` (`lib/audit-display.ts`).
- **`/exodus/architecture`** — informational, terminal-style copy: the actors (human, agent, homelab-api, Postgres), a Swagger link (`HOMELAB_API_PUBLIC_URL` + `/docs`), the MCP tools and playbook read live from `POST /mcp`, and the Exodus REST routes read from `GET /openapi.json`, badged `hud · <page>` (a home-hud page calls it, from `x-home-hud`), `agent · <tool>` (from `x-mcp-tool`), or `swagger only`. Each section shows its own error if homelab-api is unreachable.
- **`/exodus/jobs`** — jobs across all sources, filterable by source through a `?source=<id>` URL parameter. Status and root link to the job's detail page.
- **`/exodus/jobs/[id]`** — what a run did, directory by directory: the job's status, counts and error, and its queue items (oldest first, at most 500) filterable by `?status=`. Each row expands to show why the directory was queued, what the agent concluded, the paths it skipped, the name patterns it skipped (`skippedGroups`, e.g. `*.msi ×212`) and the last error. While the job is active the page refreshes every 5 seconds and offers a Queue Directories form (one path per line, optional priority) to point the agent at more places inside the job root; paths already in the job are reported, not duplicated.

## File preview

A spyglass button (`radix-magnifying-glass` from `@abbottland/fui-icons`) opens a modal with the file's contents, read live from the source. It appears next to the path of file inventory items (table, cards and detail modal on `/exodus/inventory`) and on each skipped path on the job page, but only for previewable extensions (images, PDF, and text such as `txt` and `xml`; `app/exodus/lib/preview.ts` mirrors the API's list). The modal fetches through the same-origin proxy `app/exodus/preview/route.ts` so a failure (no connection, file gone, not in the inventory) shows the API's message instead of a broken image.
