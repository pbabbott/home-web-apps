# Exodus - Data Model

[← Project Exodus](./README.md)

Six tables. The split that matters: a **job** is one run over a source and owns the lifecycle; a **queue item** is one bounded unit of work _within that job_ and tracks only its own state; a **inventory item** is the agent's proposed backup unit, which a human decides on.

- **`sources`** — a machine being inventoried: `name` (unique), `source_type` (only `windows` today), and an optional `host_id` that references `hosts.id`, so a source can be joined to the registered host for its name and IP. Sources need not be linked to a host. The foreign key is `ON DELETE RESTRICT`: deleting a host that still has a source returns 409 instead of silently wiping its discovery history.
- **`discovery_jobs`** — one run over a source, rooted at `root_path`. Status: `pending` → `running` → `completed` | `failed` | `cancelled`. A partial unique index allows only **one active (pending/running) job per source**.
- **`discovery_queue_items`** — one directory to explore within a job. Status: `queued` → `in_progress` → `completed` | `skipped` | `failed`. `job_id` is required and cascades on delete; unique on `(job_id, normalized_path)`. The source is reached through the job. Fields: `priority` (higher claimed first), `attempt_count`, `max_attempts` (default 3), `last_error`, `available_at` (retry backoff), and the lease (`claimed_by`, `claim_token`, `lease_expires_at`). `reason` records why it was queued and `result` (`{ summary?, skipped: [{ path, reason }], skippedGroups?: [{ pattern, count?, reason }] }`) what the worker concluded, including paths it deliberately did not queue. No job-level lifecycle is duplicated on items.
- **`inventory_items`** — see [Inventory Items](./inventory.md). Unique on `(source_id, normalized_root_path)`. Agent-owned recommendation columns and human-owned `decision*` columns; `first_job_id` / `last_job_id` (set null if a job is deleted); a `CHECK` that `decided_at` is set unless `decision` is `pending`.
- **`exclusion_rules`** — see [Exclusion rules](./exclusion-review-audit.md). `source_id` is null for a global rule; unique on `(source_id, normalized_path)` with `NULLS NOT DISTINCT`.
- **`audit_events`** — append-only log. Its id columns have **no foreign keys** so events outlive the rows they describe.

**State checks.** `discovery_queue_items` has `CHECK`s that `0 <= attempt_count <= max_attempts` and that an `in_progress` item has `claimed_by`, `claim_token` and `lease_expires_at` all set; `inventory_items` checks `decided_at` is set unless `pending`. The queries already keep to these, so the database now rejects an illegal state instead of storing it.

Migration history: `0003` created the tables with a `hostname` text column, `0004` replaced it with a required `host_id`, `0005` made `host_id` optional, `0006` scoped the queue to its job (see Decisions) and added a per-path catalogue table (since removed, then reintroduced under the same name by `0012`), `0007` added the `CHECK` constraints above, `0008` renamed `backup_sources` to `sources` (the enum, the table and its constraints, all in place, so no data moved), `0009` added `exclusion_rules`, `audit_events` and the catalogue review columns, and `0010` added `review_candidates` and the queue item `reason` / `result` columns, migrated reviewed catalogue rows into it, and dropped the catalogue review columns. `0011` dropped the old catalogue table and the audit `inventory_item_id` column, deleted the legacy `inventory_item.review_*` audit events, and renamed the `inventory_item_type` enum to `candidate_kind`. `0012` renamed `review_candidates` to `inventory_items` (table, enums, constraints, indexes, `audit_events.review_candidate_id` → `inventory_item_id`, and the `review_candidate.*` audit event types → `inventory_item.*`) in place, so no data moved.
