## Check before ordering

- [ ] **What the $799 includes.** The store labels it both "barebone" and "32GB RAM+1TB SSD". Confirm it is the barebone (no RAM, no SSD, no OS).
- [ ] **Which CPU the variant has** (9955HX or 7945HX) and the RAM speed that goes with it (DDR5-5600 or 5200).
- [ ] **Compare the Amazon price** ($839.99 in January 2026) and its return window against the store's 30 days. Pick the seller with the better returns.
- [ ] **Price the RAM for real.** The $400–560 figure is an assumption from desktop DDR5. Find actual DDR5 SO-DIMM 2 × 16 GB kits, with speed and CL.
- [ ] **Price the drives.** Current 2 TB TLC/DRAM prices (SN850X was about $354). Price 1 TB drives too. Avoid DRAM-less and QLC drives.
- [ ] **Price a power-loss-protected drive** that fits (22110 for slots 2–3, or U.2 for slot 1), if you want one. None priced yet.
- [ ] **Read the Proxmox reboot thread** (kernels 6.14 and 6.17) and the Level1Techs "won't post" thread, and look for newer MS-A2 reports from October 2026.
- [ ] **Check the BIOS situation:** which version ships now, and whether 1.03 is still reported to break things.
- [ ] **Confirm the room:** space, airflow, a power outlet, and that about 50 dBA under load is tolerable where it will sit. Check the 1 GbE switch has a free port.
- [ ] **Keep the budget check:** total including tax and shipping stays under $2,600.

**Not found:** any Proxmox 8.x (kernel 6.8) report on the MS-A2 beyond the installer hang, and any fix for issue 1. Whether 6.14.8-2 is still installable from the repository was not checked.

**Test plan for the 30-day window:**

1. Install Proxmox. If the installer hangs, retry with a ZFS root, or install Debian first and add Proxmox on top. Record which method worked.
2. **Pin an older, known-good kernel** (`proxmox-boot-tool kernel pin <version>`), starting with 6.14.8-2 if available. Keep the default kernel installed.
3. Run on the pinned kernel for a week under CI load. Watch `journalctl -b -1` after any reboot and `last -x reboot`.
4. Optionally repeat on the newer kernel to see whether the reboots reproduce on your unit. Only do this if the first week is clean.
5. Set slots 2–3 to PCIe 3.0 (the default) at first; two reporters' stable setups ran NVMe at 3.0. CI is latency-bound, so Gen3 x4 should cost little. Test 4.0 afterwards.
6. Do not enable IOMMU passthrough unless needed.

**Return trigger:** any unexplained reboot that survives the kernel pin, or an installer that cannot complete with ZFS or Debian-then-Proxmox.

**How this changes the odds:** these are real, current, unresolved reports on this exact box. The 30-day return makes it safe to try, but I would treat the first week as a stability test and not a formality. The MS-03 and the other candidates have fewer reports, which does not mean fewer problems.

## On arrival (start the 30-day clock the day it ships)

- [ ] Note the delivery date. **Decide by day 25** so a return is still possible.
- [ ] Do **not** update the BIOS. Record the shipped version.
- [ ] Set BIOS: virtualization and IOMMU on, "restore on AC power loss", and slots 2–3 to **PCIe 4.0**.
- [ ] Install Proxmox (see the known-issues test plan: ZFS or Debian-then-Proxmox if the installer hangs). Note the kernel version, pin a known-good kernel, and keep a fallback.
- [ ] Check the drives: `nvme list` shows the model and PCIe link speed for each slot (`lspci -vv` link status).
- [ ] Measure **idle power** with a plug-in meter (one owner reported about 75 W idle, probably an outlier).

## Within the 30 days

Run the acceptance test from the [criteria doc](./2026-10-22-hardware-purchase-criteria.md#6-acceptance-test-run-within-the-return-window). Pass or return:

- [ ] `fio` tests T1–T4 on the new drive ([commands](./2026-10-22-hardware-bottleneck.md#test-commands-copy-and-paste)), results filled in beside the old host and ELDERWAND.
- [ ] 30-minute all-core load (`stress-ng --cpu 0 --timeout 1800s`) with temperature logged: **CPU under 85 °C, no throttling.** Note the fan noise.
- [ ] 30-minute `iperf3` to another host, no drops in `dmesg` or the switch counters. Repeat after a reboot.
- [ ] **Reboot watch:** leave it under CI load for at least a week. Any unexplained reboot counts against it.
- [ ] Join one worker VM to the Kubernetes cluster, label it for CI, and run one full `ci.yml` on a fresh SHA. Target: disk write latency under 5 ms average and IO pressure under 0.15 (same Prometheus queries as the analysis).
- [ ] If a 22110 or U.2 power-loss-protected drive is bought, repeat T2 (the flush test) on it and compare.

**Return if:** unexplained reboots, thermal throttling or CPU over 85 °C, NIC dropouts, or a dead or unstable unit.
